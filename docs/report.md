# ASUS ROG Azoth 96 HE — OLED USB HID протокол (первичный анализ)

**Дата:** 2026-10-02 · **Платформа захвата:** Windows 11, USBPcap 1.5.4.0 + tshark
**Устройство:** VID `0x0B05` PID `0x1C10`, драйвер-фильтр USBPcap на корневом хабе `\\.\USBPcap2` (клавиатура за внешним хабом Genesys `05E3:0610`, адрес на шине = 3)
**Хост-софт:** GearLink (GearLink_KBService / KBAgent / KBProcess / UtilityCompanion)

Все файлы лежат в `C:\azoth-capture\`. Захват: `USBPcapCMD.exe -d \\.\USBPcap2 -A --inject-descriptors -o <file>.pcap` (формат libpcap, snaplen 65535). Управление записью — через elevated-агент `agent.ps1` (командный файл `queue\action.txt`), потому что USBPcapCMD требует админа и не умеет останавливаться по таймеру.

---

## 1. Карта устройства (из 00-enumeration.pcapng, переподключение на t=2256.5 с)

Конфигурация 1, wTotalLength=116, все интерфейсы HID:

| Interface | Назначение | Endpoint | Dir | MaxPacket | bInterval |
|---|---|---|---|---|---|
| 0 | boot keyboard | 0x81 | IN | 64 | 1 |
| 1 | **vendor (канал OLED/статуса)** | **0x01** | **OUT** | **64** | **4** |
| 1 | | **0x82** | **IN** | **64** | **4** |
| 2 | consumer control (медиа) | 0x83 | IN | 64 | 1 |
| 3 | доп. клавиатура | 0x84 | IN | 64 | 1 |

Report-дескрипторы всех 4 интерфейсов прочитаны Windows при энумерации и извлечены из дампа → `descriptors\iface{0..3}.reportdesc.hex`.

**Интерфейс 1 (34 байта) — ключевой:**
```
06 00 FF    Usage Page (Vendor 0xFF00)
09 01       Usage 0x01
A1 01       Collection (Application)
  09 02  75 08  95 40  15 00  26 FF 00  81 02   Input: 64 байт   ← EP 0x82
  09 03  75 08  95 40  15 00  26 FF 00  91 02   Output: 64 байта ← EP 0x01
C0          End Collection
```
Сырые 64-байтные репорты без HID report ID: **первый байт payload = байт команды (opcode)**.

Дескрипторы iface0 (68B, стандартная boot-клавиатура) и iface2 (186B: consumer-битмап 20 флагов + vendor-блок + pointer-коллекция) — в файлах рядом.

## 2. Формат обмена интерфейса 1

Каждая команда хост→клавиатура (EP 0x01 OUT, ровно 64 байта, паддинг нулями)
подтверждается **эхо-ACK на EP 0x82 IN** с тем же payload (иногда + доп. статусные байты).
Команды наблюдались одиночно и пачками с интервалом 2–10 мс.

### 2.1 Таблица команд (opcode = байт 0)

| Opcode | Payload (значимые байты) | Направление | Смысл (гипотеза, уверенность) |
|---|---|---|---|
| `0x12` | `12 01 00…` / `12 00 00…` | OUT | Опрос статуса, два чередующихся варианта. Ответ: `12 01 00 00 00 64 04 02 01 14 64 27 11` / `12 00 00 00 30 00 07 00 06 00 01 01 00` |
| `0x63` | `63 00 00 00 00 [EA 07][0A][02][11][35] 00` | OUT | **Установка даты/времени**: год u16 LE (0x07EA=2026), месяц, день, час, минута, (+сек?). Слит при применении конфигурации экрана. Этим «оживают» часы после сна |
| `0x51` | `51 0C 00 00 [V] 00 00` | OUT | **Громкость для OSD качельки**, V = проценты 0–100 (наблюдалось 0x1E/0x20/0x22/0x24, шаг 2 за щелчок) |
| `0x25` | `25 0C 00 00 [hi][lo]` | OUT | Второй вариант громкости-OSD, значение ~2468 (0x09A4→0x09A6, шаг 1/тик). Возможно, raw-значение или другой режим качельки. Требует уточнения |
| `0x6A` | `6A [scr][?][?][mode][param]` | OUT | Конфигурация экрана/виджета. Наблюдения: выключенный виджет → одиночная `6A 00 00 00 03 00`; два индикатора → пара `6A 00 00 00 03 01` + `6A 01 00 00 03 00`; byte4: 03 vs 01 (двойной/одинарный?) |
| `0x24` | `24 01 00 00` (ACK: `24 01 00 00 03`) | OUT | Часть пачки применения конфигурации |
| `0x68` | `68 00 00 00 64 00 00` (0x64=100) | OUT | Часть пачки применения (яркость/контраст=100?) |
| `0x50` | `50 55 00 00` | OUT | Финализатор пачки (commit) |
| `0x6B` | `6B 00 00 …` | OUT | **Начало режима загрузки картинки** |
| `0x61` | см. §2.2 | OUT | **Поток данных битмапа** |
| `0x66` | `66 00 01 00 00 00 [usage][?] 00 01 00 [temp] 00` | OUT | **Пуш метрик CPU**: byte6 = usage % (0x14=20% покой, 0x48=72% под лагом), byte10 = температура °C (0x30=48, 0x46=70). Event-driven — шлётся при изменении, именно он питает индикаторы OLED |
| `0x27` | `27 00 00 00` | OUT | Единичный сигнал без параметров. Появлялся при действиях в GearLink UI и во время 100% нагрузки CPU. Гипотеза: уведомление/триггер (например «CPU high» или «перерисуйся»). Не расшифрован |

### 2.2 Протокол загрузки битмапа (opcode 0x61) — разобран полностью

> **Уточнено 2026-10-03 по декомпиляции** (`CustomAnimation_RGB_Type_1.cs`, `ConvertImageToBinary_RGB_Type_1.cs`):
> это канал Custom Animation (полноэкранная картинка/GIF). Последовательность:

```
6A 00 00 00 00 01 00 00            — переключить экран 0 в режим картинки (?)
6B 00 00 00 …                      — BEGIN (опкод НЕ найден в .NET-коде — нативный/легаси-путь)
61 01 00 00 68 02 00 00 …          — SetCustomAnimationMode: [seq u16=0][total u32 LE] = 616 чанков
61 02 67 02 00 00 | 01 00 e8 03 | <58 байт данных>   — chunk: [idx u32 LE]=615 + данные;
                                     первые 4 байта бинарника = заголовок [frames u16 LE][duration u16 LE]
                                     (1 кадр, 1000 мс) — «мета» расшифрована
61 02 66 02 00 00 | <58 байт>
61 02 65 02 00 00 | <58 байт>
…                                  — индекс УБЫВАЕТ 615 → 0 (u32 LE, а не u16 BE) (передача задом наперёд)
61 02 00 00 00 00 | <30 байт данных> <28 байт 00>    — chunk #0, в конце паддинг
61 03 00 00 …                      — SetCustomAnimation_ShowOnly (END)
6A 01 00 00 …                      — применить (экран 1?)
68 00 00 00 64 …                   — яркость/показ
50 55 00 00                        — commit SetProfile
```

**Геометрия кадра (подтверждено арифметикой и полярностью заливки):**
- Чанков 616 × 58 байт = 35 728; минус 4 байта заголовка (frames=1, duration=1000мс), минус 28 паддинга = **35 696 байт полезных**
- 35 696 = **184 × 97 × 2** → панель **184×97 (ландшафт), RGB565 LE**; статичная картинка вращается
  хостом на 90° CW перед отправкой (буфер портретный 97×184, как у music mode)
- Белый кадр = байты `FF FF` на пиксель, чёрный = `00 00` (заливки в 06-custom-image.pcap)
- GIF: бинарник = `[frames u16][duration u16 × frames]` + кадры; **устройство анимирует цикл само**,
  хост после загрузки ничего не шлёт. Кадры GIF НЕ вращаются хостом — готовить в ориентации панели
- ACK: каждые 20 чанков + последний; `FF AA` = запрос ретрансмиссии с индексом u32

### 2.3 Канал клавиатура → хост (IN)

| Endpoint | Payload | Смысл |
|---|---|---|
| 0x82 | эхо всех команд интерфейса 1 (иногда + статус) | ACK-канал |
| 0x83 | `01 00 <bitmap20> 00` | consumer-репорт iface2 (нажатие/отпускание медиа/громкости): бит4=Play/Pause, бит6=Prev, бит7=Next (нажатия в 07); volume inc/dec = байт 2, биты 1–2 (тики качельки) |
| 0x83 | `03 72 [01\|04\|02] 00…` | событие качельки/медиа-клавиши: 01=поворот вверх, 04=вниз, 02=?; 00 = отпускание. Пара к каждому consumer-репорту |
| 0x83 | `03 91 00 00 [n]` | тики качельки в режиме громкости (счётчик тиков), до 6 подряд |
| 0x83 | `03 71 [00\|04\|10] 00` | нотификация о нажатии клавиши (сопровождает модификаторы iface0; 04 при Alt+Tab, 10 при Shift) |
| 0x81 | стандартные boot-клавиатурные репорты (без report ID): `02 …`=LShift, `04 … 2b`=LAlt+Tab и т.п. | iface0 |

## 3. Поведенческие выводы (для реализации на macOS)

1. **Архитектура — сценарий (B): команды + режим загрузки битмапа.** Экранные режимы (виджеты/картинка) переключаются командами (`6A`-пачка), кастомный контент льётся битмапом 184×97 RGB565 через `6B/61/61 03`.
2. **Виджеты (часы, CPU) рисует сама клавиатура.** Хост не шлёт кадры часов; он: (а) синхронизирует время командой `63` (редко, при применении конфигурации), (б) пушит метрики CPU командой `66` при изменении.
3. **Часы «замерзают» при сне OLED** — дисплей перестаёт перерисовываться, время не тикает. Пробуждение: действия в GearLink (конфиг-пачка с `63`). Нажатия клавиш и щелчок качельки в наблюдениях НЕ будили экран и не порождали команд хоста.
4. **Громкость Windows не доходит до клавиатуры** (04b-mute: 0 пакетов при mуte с ноутбука). Индикатор громкости на OLED живёт только в режиме качельки: тики `03 72`/`03 91` → хост меняет громкость системы → отвечает `51 0C 00 00 <проценты>` (или `25 0C …` в другом варианте) для отрисовки OSD.
5. **Медиа-клавиши** Azoth — обычные consumer-репорты на iface2 (`01 00 …`), хост на них OLED-команд не шлёт (07).
6. Частота опросов `12` неравномерна: ~1 Гц после активности пользователя, затухает до ~0.1 Гц в покое; в спящем режиме — единичные.

## 4. Открытые вопросы (добор на следующей итерации)

- `27`, `24`, `50 55`, `68` — точная семантика; params `6A` (карта режимов экранов/виджетов, «несколько экранов»).
  *(частично закрыто 2026-10-03: `0x24 01` = GetOledMode (GetOledMode_Type_1), `50 40/55/60/61` = коммиты SetProfile_Type_1; `0x27` и `0x6A/0x6B` в .NET-коде не найдены — нативный/легаси-путь)*
- ~~Мета `01 00 e8 03` первого чанка битмапа~~ — **решено**: заголовок анимационного бинарника
  `[frames u16 LE][duration u16 LE, мс]`; статика = 1 кадр 1000 мс. GIF — по кадру на длительность,
  устройство зацикливает само.
- ~~Порядок байт RGB565 (LE/BE)~~ — **решено 2026-10-03: LE** (младший байт первый). Подтверждено декодированием
  текстовых битмапов music mode (см. `music-mode.md` §5): BE даёт цветные ореолы, LE — чистый текст.
- «Разбудить» OLED программно (для стороннего приложения) — какой командой; возможно `6A`-пачка или `27`.
- `0x25 0C` vs `0x51 0C` — два формата значения громкости (зависит от режима переключателя сбоку?).

> **Продолжение анализа:** `music-mode.md` — компоненты GearLink, music mode (эквалайзер + трек),
> опкод `0x67`, конвейер KBAgent→KBApi, декодирование битмапов, сравнение всех трёх каналов
> загрузки графики (`0x61` анимация / `0x62` баннер / `0x67` music).

## 6. Ключевые команды tshark

```bash
T="/c/Program Files/Wireshark/tshark.exe"
# весь трафик клавиатуры с полезной нагрузкой
"$T" -r 06-custom-image.pcap -Y "usb.device_address==3 && usbhid.data" \
     -T fields -e frame.time_relative -e usb.endpoint_address -e usbhid.data
# только команды хост→клавиатура (интерфейс 1)
"$T" -r 06-custom-image.pcap -Y "usb.device_address==3 && usb.endpoint_address==0x01 && usbhid.data" \
     -T fields -e frame.time_relative -e usbhid.data
# чанки битмапа
"$T" -r 06-custom-image.pcap -Y "usbhid.data[0]==0x61" -T fields -e frame.number -e usbhid.data
# дескрипторы из энумерации
"$T" -r 00-enumeration.pcap -Y "usb.idVendor==0x0b05" -V
# hexdump кадра
"$T" -r 00-enumeration.pcap -Y "frame.number==2520" -x
```
