# M901 (ROG Azoth 96 HE) — громкость, качелька и OSD: полная цепочка

Дата: 2026-10-02. База: `m901_keyboard_app.bin` @ **0x0E066000** (все адреса абсолютные).
Закрывает открытый вопрос из `report.md` §4 («0x25 0C vs 0x51 0C») и подтверждает механизм
«качелька → событие хосту → хост возвращает громкость → OSD» по коду прошивки.

---

## 0. Главный вывод

1. **Формат значения громкости один: `51 0C 00 00 [V]`, V = проценты 0–100.**
   Никакого «raw-варианта» не существует.
2. **`25 0C` — это НЕ громкость.** Это геттер привязок спец-клавиш качельки (матричные
   0xD4/0xD5/0xD6) к LED-позиции, постранично. GearLink опрашивает его циклически
   (`25 0C 00 00 09 A4/A5/A6` каждые ~46 кадров), и в захвате 04-mute он случайно
   совпал по времени с громкостной сессией — отсюда ложная гипотеза «второго формата».
   Ответы захвата `E8 01 / F2 01 / E9 01` (488/498/489) — коды назначений (vol−/push?/vol+),
   хранящиеся в таблице 0x230086BC+0x4BC+page·8.
3. **Условия выбора между 0x51 и 0x25 нет** — это разные команды с разным смыслом.
4. OSD рисует **sysctrl** по IPC из keyboard app; клавиатура сама громкость не хранит
   (кроме write-only копии в 0x23013A4C) и сама громкость не меняет — она только шлёт
   consumer-события и ждёт `51 0C`.

## 1. Полный цикл качельки в режиме громкости (захват + код)

```
поворот качельки вверх
  └─ EP 0x83 (iface2): 01 00 04 00 …    consumer-репорт ID 1, бит10 = Volume Increment (HID 0xE9)
  └─ EP 0x83 (iface2): 03 72 01 00 …    vendor 0xFFC0 репорт ID 3 «качелька: вверх»
       (вниз: 01 00 02 00 [Vol Decr 0xEA] + 03 72 04; отпускание: 01 00 00 00 + 03 72 00)
Windows меняет громкость системы → GearLink:
  └─ EP 0x01 (iface1): 51 0C 00 00 [V]  новое значение в процентах, шаг 2 за щелчок
клавиатура:
  └─ ACK EP 0x82: 51 0C 00 00 [V]       (эхо-ответ, payload[0] = V)
  └─ IPC 0x26 в sysctrl: {subtype 0x14, x = 0x5C−6·len, len+1, строка "V%"}
  └─ IPC 0x16 в sysctrl: {subtype 0x14|0x16, timeout=1000, gate, 1} — скрытие OSD
```

Отличие захвата 03b (шаг 2%, оба направления) и 04-mute (`51 0C` не было —
Windows-громкость не менялась, см. report.md §3.4: OSD живёт только на тиках качельки).

## 2. Опкод 0x51 sub 0x0C — Volume OSD set (0x0E07CC03)

Запрос: `51 0C [echo:u16] [V] …`. Диспетчер sub-таблицы опкода 0x51: **0x0E07B309**,
таблица @**0x0E07B318** (145 слотов, sub ≤ 0x90, база = 0x0E07B318, слот 0x0C → 0x0E07CC03).

| echo | Ветка | Действие |
|---|---|---|
| **0x0000** (GearLink) | 0x0E07DF8C | если `[0x23000CA0] != 0` → только ACK. Иначе: `[0x23006F68] = 1000` (каунтер OSD); subtype таймера = `[0x23006F68+4]==0 ? 0x16 : 0x14`; **0x0E08C4E4(V)** — формат «V%» и IPC 0x26; **0x0E08C548(subtype, 1000, 0, 1)** — IPC 0x16 таймера скрытия (3-й аргумент — константа 0, уточнено по декомпиляции 0x0E07CC02); затем общий ACK |
| **0x0001** | 0x0E07CC10 | **сохранение**: `[0x23013A4C+1] = 1` (флаг валидности), `[0x23013A4C+2] = V` (проценты). Ридеров этой структуры в образе нет (только 2 писателя: здесь и 0xFA) — копия «последней громкости», возможно для другого ядра |
| прочее | 0x0E07CC1A | голый ACK |

**Ответ (все ветки):** `51 0C <echo:u16> <len=1> [payload[0]]`, строитель 0x0E078DEC копирует
payload из буфера аргументов **0x2300CB20** (= pkt+4), т.е. payload[0] = V — ACK-эхо с
значением. Подтверждено захватом: `51 0c 00 00 20` → ACK `51 0c 00 00 20`.

### 2.1 Форматтер OSD 0x0E08C4E4

- 0x0E096780 — десятичный → ASCII (делягия 0xCCCCCCCD), 0x0E0967D8 — hex → ASCII;
- буфер на стеке: строка `"<V>%"` (байт `%` = 0x25 дописывается в конец);
- IPC-конверт (enqueue 0x0E083A38 — кольцо 49×64 Б @0x23012B10):
  `[0x26][0x5C−6·len][0x14][len+1][байты строки]`, длина len+5.
  **IPC id 0x26 = «текст громкости OSD»**: поле 2 = x-позиция текста (центрирование:
  92 − 6 пикс × цифры), поле 3 = длина строки.
- 0x0E0BFCF0 — копия строки в конверт.

### 2.2 Таймер скрытия 0x0E08C548

Строитель 7-байтного IPC: `[0x16][r0 subtype][r1 timeout u16][r2 gate u16][r3]` → 0x0E083A38.
**IPC id 0x16 = «расписание сна/восстановления экрана»** (её же зовёт опкод 0x72:
`0x0E08C548(pkt[5]+0x48, 1000, 0)`). Для громкости: timeout = **1000 тиков** —
 OSD гаснет через ~1 с после последнего `51 0C` (каждый тик качельки → новый `51 0C`
 → таймер перезапускается записью `[0x23006F68]=1000`).

### 2.3 Гейт [0x23000CA0] (= 0x23000C98+8)

Байт состояния (значения 0..3 встречаются: RGB-функция 0x0E08A3E0 сравнивает с 2 и 3).
`51 0C` echo 0 рисует OSD только при `[0x23000CA0]==0`. Пишется вычислительно
(литерала 0x23000CA0 в образе нет — доступ через базу 0x23000C98), точный писатель
не локализован; тот же байт видно в дампе `12 00` (payload[8]).

## 3. Опкод 0x25 sub 0x0C — геттер привязок качельки (0x0E07B930), НЕ громкость

Запрос: `25 0C [echo:u16] [page][usage_lo][usage_hi]`. Диспетчер опкода 0x25: **0x0E07B55C**,
sub-таблица @**0x0E07B56C** (39 слотов, sub ≤ 0x25; `0x0C` → 0x0E07B930).

```
page  = pkt[4], допустимо 0..0x0A (иначе NAK 0x0E07A7C8)
usage = pkt[5] | pkt[6]<<8 (u16 LE)
matrix = LUT_0xE0C125C[usage]           ; HID usage → индекс матрицы
  0xD3 → usage 0xA3, 0xD4 → 0xA4, 0xD5 → 0xA5, 0xD6 → 0xA6; прочее → NAK (FF AA)
value  = u16 @ (0x230086BC + page*8 + {0xD4→0x4BE, 0xD5→0x4BC, 0xD6→0x4C0})
         (исправлено 2026-10-03 по декомпиляции 0x0E07B930/0x0E07E1E4/0x0E07E1F4:
          0xD4 читает +0x4BE, 0xD5 — +0x4BC; в старой редакции было перепутано)
трансформация value (подтверждено декомпиляцией и дизассемблером):
  4..0x7F          → LED = LUT_0xE0C1188[value]        (usage → LED-позиция)
  0xE0..0xE7       → LED = LUT_0xE0C1188[value − 0x70]
  0xD0..0xD6       → LED = LUT_0xE0C1188[value − 0x30]
  0xF0..0xF6       → LED = LUT_0xE0C1238[value − 0xF0]
  0xA0D3           → спец-ветка 0x0E07E01E (результат 0xD3)
  0xA0E6..0xA0EB   → value − 0x9DE6 (0x300..0x305)
  прочее           → вернуть как есть (u16)
Ответ: 25 0C <echo> <len=2> <value u16 LE>
```

**Таблица привязок:** 11 записей × 8 байт @ `0x230086BC+0x4B8` (page = индекс профиля):
u8 @+0x4BA+page·8 (читается `25 0B`), u16 @+0x4BC/+0x4BE/+0x4C0+page·8 — назначения
трёх «спец-клавиш» (матрица 0xD4/0xD5/0xD6 = качелька влево/вправо/нажатие) для страницы.
Захват 04-mute: page 9, usages A4/A5/A6 → `E8 01` (488), `F2 01` (498), `E9 01` (489) —
коды назначений (соседние 0x1E8/0x1E9 = vol−/vol+, 0x1F2 = push — внутренняя нумерация
назначений, НЕ проценты).

Соседние геттеры того же семейства:
- `25 0B` (0x0E07B81A) → 11 байт таблицы 0x230086BC+0x4BA+page·8 («батарея/состояние страницы»);
- `25 0A` (0x0E07B844) → per-device состояние ([0x23015EF8]+dev·8, dev = [0x23000C98+6]).

## 4. Генераторы IN-событий iface2 (EP 0x83)

Транспорт: **0x0E091E90(report_id, buf, len, flags)** — единая точка отправки IN
(iface2; внутри — маршрутизация USB/BT: флаг 0xDEADBEEF @0x23015F70, [0x23015EF4] бит2,
[0x23019558]). Прямых вызовов два: 0x0E07A69C (стрим лог-канала `FB 03`, report r0=2)
и задача **0x0E091EF4** (все репорты `01/03 …`, len = 0x15 = 21).

| Репорт | Буфер | Кто строит |
|---|---|---|
| `03 72 xx` (качелька) | 0x2301924C | сеттер битов **0x0E091CE4** (usage 0xD4..0xD6 → LUT **0x0E0C0E5C** = {0x20,0x21,0x22} → биты 0/1/2 байта 2 буфера) + отправитель **0x0E092072** (`movw r5, #0x7203` → `03 72`, xx = биты состояния) |
| `03 71 xx` / `03 61 xx` (клавиши; 0x61 — BT-вариант) | 0x23017D1C | отправители **0x0E0920E4** / **0x0E0920CE** (`movw #0x7103 / #0x6103`); ветки задачи 0x0E091EF4 (`ite ne: movne r3,#0x61; moveq r3,#0x71` по флагу BT/USB) |
| `03 91 00 00 [n]` | очередь событий @0x23018D08 (7-байтные записи `{type u8, val u16, u16, u16}`, head 0x23018D00, tail 0x23018D04, ≤109) | дренаж очереди @0x0E09201A → репорт `03 <type> <val lo> <val hi> <u16> <u16>`; продьюсер — **0x0E09228C(r0=type, r1, r2, r3)**, известные вызовы — RGB-события type 0x75/0x77/0x7C/0x7D (0x0E08A3E0, с LUT 0xE0C1188 и цветами 0x23008EF4/0x23014B14). Продьюсер type 0x91 не найден по инструкции-иммедиату; по захвату 04-mute `03 91 00 00 n` — **периодический (~650 мс) счётчик фаз n = 00..05**, тикающий без ввода, пока активна сессия качельки/OSD (кандидат: таймер-таск, состояние [0x23019510]) |
| `01 00 <bitmap20>` (consumer, media-клавиши) | слоты кольца 0x23019264/0x2301927C (по 24 Б, head 0x23019294/0x23019298) | сеттер **0x0E091CE4** (путь r0==0): LUT **0x0E0C0E60** (внутренний код → № бита); сборка 21-байтного слота @0x0E091D26 |

Внутренние коды → биты consumer-битмапа (LUT 0x0E0C0E60, проверено побайтово):
- **0x2B → бит 10** (0x22 → байт2 бит2 = `01 00 04`) = **Volume Increment (HID 0xE9)**;
- **0x35 → бит 9** (0x21 → байт2 бит1 = `01 00 02`) = **Volume Decrement (HID 0xEA)**;
- **0x39 → бит 11** (0x23 → байт2 бит3 = `01 00 08`) = **Mute (HID 0xE2)** (по позиции;
  в захватах mute с клавиатуры не тикался — report.md §03/04b).
Диапазоны кодов в 0x0E091CE4: 0x04..0x7F → LUT0[код]; 0xE0..0xE7 → LUT0[код−0x70];
0xF0..0xF5 → LUT0[код−0x77]; 0x87..0x8A → LUT0[код−0x1F]; 0x90 → LUT0[0x6D];
0xD4..0xD6 → LUT 0x0E0C0E5C (качелька, буфер `03 72`). Прочее — игнор.

Usages 0xE9/0xEA/0xE2 подтверждены: это то, что видит Windows (consumer-битмап iface2,
дескриптор @0x0E0C25B0); в прошивке им соответствуют внутренние коды 0x2B/0x34/0x37.
Хост-соftware сам дергает громкость Windows от этих репортов и возвращает `51 0C`.

`03 72 02` из report.md («?») — по коду: бит1 буфера 0x2301924C = usage 0xD5 —
среднее положение/нажатие качельки; наблюдаемое «02» = комбинация битов нажатия.

## 5. Опкод 0x12 — таблица полей (ground truth из захватов)

Sub-таблица: jt **@0x0E07A744** (23 слота, sub ≤ 0x16), sub 0 → **0x0E07A989**,
sub 1 → **0x0E07AAC9** (совпадает с захватом; полное декодирование — `PROTOCOL_STATUSBAR.md` §6).

| 0xC0 | 0x0E07C0AB | системные: sub 0x81 read / 0x83 write (см. PROTOCOL.md §3.4) — риск! |
| 0xFA | 0x0E07BE5F | sub 0: echo == **0xA5D3** → **0x0E07D750: софт-разблокировка гейта** ([0x23015EF8+0x10]=1, [0x2301D25F]=1, restore-конфиг 0x0E0816BC) — НЕ уводит в bootloader; прочий echo → [0x23015EF8+0x10]=0 и бит0 0x23013A4C=0 (закрыть) |

Ветки главного диспетчера помимо таблицы: `0x12` → jt @0x0E07A744; `0xC0` → 0x0E07A7D0
(sub 0x81/0x83); `0xFB` → 0x0E07CCBE (см. §7); `0xFD` → 0x0E07A6F4 (sub > 0xA1 → 0x0E07CD5C;
sub 0xA0/0xA1 → 0x0E07D306); прочее > 0xFB → 0x0E07D592. Старая разметка «CMD 0xFD g2/g1-g7»
в handlers_all.txt — ошибочна (0xFD обслуживается только sub 0xA0-0xA2+).

## 7. Скрытые/неразобранные команды и риск

| Команда | Адрес | Что делает | Риск (живой девайс) |
|---|---|---|---|
| `FA 00 <echo 0xA5D3>` | 0x0E07D750 | **софт-анлок гейта** без перезагрузки (разрешает 0x61/0x62/0x67/0x6B/0xC0) | средний: открывает небезопасные команды; сам по себе обратим (`FA 00 <др. echo>` закрывает) |
| `B0 00 00 00 "reset"` | 0x0E07AF04 | софт-ребут (ASCII-магия «reset») | **не слать**: разрыв соединения |
| `7B AA 41 53 55 53 AA` | 0x0E090604 | bootloader (0xDEADBEEF @0x0E1A3600 + ребут) | **запрещено** (известный триггер) |
| `C0 81/83 …` | 0x0E07C0AA | staging 0x2300CB20 ↔ 0x23006F74 (форвард в sysctrl), счётчик 0x23006754; НЕ произвольная память (декомпиляция 2026-10-03, PROTOCOL_OLED.md §10.4) | **средний**: живой конфиг-путь, но адресного доступа к памяти нет |
| `FB 03 <echo = idx<<6 \| len>` | 0x0E07CCBE | лог-канал: len (≤0x20 за чанк) байт args → кольцо 0x23006E1C + idx·6 ([0x23006E18] = idx, [0x23006E60] = флаг); функция 0x0E07A640 стримит кольцо обратно на iface1 IN (префикс `03FB`) | **средний**: idx = echo>>6 при записи не ограничен сверху → запись за пределами кольца (порча RAM рядом с 0x23006Exx); len > 0x20 чанкуется. Не слать без необходимости |
| `FD A0/A1` | 0x0E07D306 | дамп/флаш транспортного кольца (0x0E0909F8, размер 0x14 или 0x3C по биту 1 [0x23015EF4]); ответ `FD <sub> <echo> <N>` | низкий: только чтение буфера |
| `FD A2 [0/1]` | 0x0E07CD5C | [0x2301D26C] = v; v==1 → 0x0E07D964, иначе 0x0E090420 (переключатель режима/стека) | средний: меняет режим соединения |
| `80 20..0x27` | 0x0E07AF48 | RGB-конфиг (режим 1/2, [0x230067A4] = pkt[4]), сохранение во флеш | низкий-средний: пишет конфиг в флеш (износ/сброс настроек) |
| `51 00 [0..6]` | 0x0E07CA19 | [0x23006FC8+1] = v (схоже с выбором слоя/режима RGB; [0]=2, флаги +0x100/+9бит) | низкий |
| `51 0A [0/1]` | 0x0E07C9F3 | бит5 [0x230086BC+0x4B1] (зарядка/LED-флаг) | низкий |
| `51 60 <u16>` | 0x0E07CA4E | [0x23000CA4] = u16 (+ вызов 0x0E08C58C) | низкий |
| `52 90` | 0x0E07B2BF | дамп 60 Б при флаге зарядки | низкий |
| `FA 00 <прочий echo>` | 0x0E07BE5E | закрыть гейт ([0x23015EF8+0x10]=0) | низкий |

Безопасно слать (только чтение): `12 sub`, `21 00`, `23 sub`, `24 sub`, `25 sub` (кроме
0x22 скан-матрицы — безвреден, но меняет LUT-кэш), `27 00 00 00`, `25 0B/0C/0A/04`, `24 *`.
Тестирование громкости — только `51 0C 00 00 [V]` (риска нет: IPC в дисплей + таймер).

## 8. Проверка клиентом

`analysis/m901_client.py` дополнен:
- `send_volume_osd(v)` — `51 0C 00 00 [V]` (echo 0) → OSD на ~1 с;

  (`01 00 04`/`03 72 01` вверх, `01 00 02`/`03 72 04` вниз) и отвечает `51 0C` с шагом 2 —
  полный громкостной цикл без GearLink/Windows.
