# M901 (ROG Azoth 96 HE) — тачскрин: декодер жестов, диспетчер, судьба свайпа ВВЕРХ

Дата: 2026-10-05. База: `m901_keyboard_app.bin` @ **0x0E066000** (ARM Thumb/M-class).
Закрывает вопрос «куда девается свайп ВВЕРХ» (живые тесты 2026-10-05:
`analysis/dircam.py`, `scan_swipe.log`, `scan_up.log`) и достраивает карту жестов,
которую `PROTOCOL_STATUSBAR.md` §7.1 пометил как «не утверждаю».

Метод: ручной дизасм (`analysis/mdis.py`) + точечная декомпиляция Ghidra (WSL,
скрипт `analysis/ghidra_scripts/DecompGestures.java`, выгрузка
`analysis/decomp_gest/*.c`) + sweep'ы BL/пулов по всему образу.

---

## 0. Главные выводы (TL;DR)

1. **Свайп ВВЕРХ обрабатывается полноценно и порождает IPC — но типа 0x95,
   неотличимого от фонового стрима состояния виджетов.** На слоте мониторинга (3)
   ВВЕРХ → конверт `{0x95, 0, 0, slot<<4|флаги, под-состояние}` — байт-в-байт тот
   же, что периодические кадры `03 95 00 00 30 00…` (~0.86 с), которые и так идут
   на шину. Поэтому хостом ВВЕРХ ненаблюдаем: ни отдельного типа, ни флага
   направления, ни «регистра последнего жеста» в прошивке нет.
2. **ВНИЗ шлёт 0x96** — тип, встречающийся ТОЛЬКО по жесту (больше его никто не
   шлёт — 3 BL-сайта 0x0E09220C на весь образ: 0x95 / 0x96 / 0x94) → единственный
   видимый хосту вертикальный жест. Практическое применение: `0396 → next` (листание вперёд).
3. **Листание «назад» страниц мониторинга в прошивке НЕ существует**: на слоте 3
   оба вертикальных направления не меняют никаких страниц (0x95 = redraw-only,
   0x96 = событие хосту). Сами «страницы» мониторинга — состояние ХОСТА (пуши
   0x66 с разными селекторами); прошивка только транслирует жест в событие.
4. **«К carousel» @0x23019014 — это НЕ страницы мониторинга**, а кольцо истории
   KPS (keys/sec) нативного тайла слота 4: 5 ячеек, индекс 0..4 c wraparound,
   писатель 0x0E093F9A (0x0E093F9E — метка внутри него), IPC {0x25, …} в sysctrl.
   Вертикальный жест на слоте 4 кольцо **СБРАСЫВАЕТ** (0x0E093F58), а не листает.
5. **Свободный канал для «назад» — двойной тап → IPC 0x94** (`03 94`, видели 2 раза
   в захвате 20): сейчас хостом игнорируется. Побочка: тоггл бит0 [0x23014B49] +
   флеш-запись конфига (0x0E081988) — семантику бит0 проверить живьём.
6. Полная карта: mode 3=ВВЕРХ, 4=ВНИЗ, 5=ВЛЕВО, 6=ВПРАВО (см. §2/§3).

## 1. Декодер тача (0x0E0810D0) — откуда берётся направление

### 1.1 Тракт данных

- **Poll-таск 0x0E081378** (стейт-машина 0..4): init/сброс контроллера тача
  (GPIO+I2C, 0x0E0832A4/0x0E083554/0x0E08335C), чтение репортов; координаты
  пишет прямо в структуру тача: `x = b[3] | (b[2]&0x70)<<4`,
  `y = (b[2]&0xF)<<8 | b[4]` (без инверсии), флаг нового сэмпла +0x28.
- **Структура тача 0x23004950** (u32-поля): `+8` x_cur, `+0xC` y_cur,
  `+0x14` тип репорта (**1 = finger down, 3 = finger up**), `+0x18/+0x1C` = start
  x/y (фиксируется при down), `+0x20/+0x24` = координаты прошлого релиза (для
  дабл-тапа), `+0x28` = «есть свежий сэмпл».
- **Фаза жеста [0x2300FA78]**: 0 → 1 при down (запомнить start); фаза 1 + тип 3
  (up) → классификация. Всё вызывается из tail таска 0x0E081378
  (`if (фаза-ворота) FUN_0e0810d0()`).

### 1.2 Классификация (0x0E0810D0, декомпил `decomp_gest/0e0810d0_*.c`)

Δx = x_cur − x_start, Δy = y_cur − y_start (экранные оси: y растёт ВНИЗ).

```
|Δx| < 0x24 (36):
    |Δy| < 0x15 (21)  → ТАП: счётчик подряд-тапов [0x2300FA70]+1 (сброс таймера
                         бездействия [0x2300FA6C] ≥ 0x191 тиков);
                         если это 2-й тап подряд и дистанция от прошлого релиза
                         < {0x24 по x, 0x15 по y} → ДАБЛ-ТАП → 0x0E08DB58
    0x27 < |Δy| (39)  → вертикальное решение (ниже)
    иначе (21..39)    → жест ГЛОТАЕТСЯ (ambiguous), фаза = 0
|Δx| ≥ 0x24:
    |Δx| > 0x31 (49) ИЛИ |Δy| > 0x27 → решение по доминирующей оси (ниже)
    иначе              → ГЛОТАЕТСЯ
```

Решение по осям (ровно из декомпила):

| Условие | mode | Физический жест | Действие диспетчера |
|---|---|---|---|
| y_cur > y_start | **4** | **ВНИЗ** | слотовый B 0x0E08D8D4 → семейство IPC **0x96** |
| y_cur ≤ y_start | **3** | **ВВЕРХ** | слотовый A 0x0E08D8B0 → семейство IPC **0x95** |
| x_cur < x_start | **5** | **ВЛЕВО** | 0x0E08CE10: слот **+1** (next) → IPC **0x93** |
| x_cur ≥ x_start | **6** | **ВПРАВО** | 0x0E08D7EC: слот **−1** (wrap 0→4) → IPC **0x93** |

Пороги в «живых» единицах не калибровались (контроллер отдаёт 11/12-битные
координаты; пороги 0x14/0x23/0x27/0x31 — сырые тики панели).

После каждого распознанного жеста: если `[0x23015EF8+0x10] != 0` (флаг
софт-разблокировки `FA 00 echo=A5D3`) и mode изменился — запомнить в
`[0x2300FA7C]` («последний жест», используется как дедуп, хостом не читается —
ср. отрицательный результат `swipereg.py`).

**Дабл-тап 0x0E08DB58**: тоггл бит0 `[0x23014B49]` + сохранение конфига во флеш
(0x0E081988) + конверт IPC **0x94** (тот же колектор, что 0x95/0x96). На шине:
`03 94 00 00 <slot<<4> <sub>`. Это и есть «EVT-94» из захвата 20.

## 2. Диспетчер жестов 0x0E08D84C(mode) — полная карта

Вход: r0 = mode 3..6. Декомпил: `decomp_gest/0e08d84c_*.c`.

```
если [0x2301D249] != 0 (wake-гейт, см. §5) → только «хвост», жест СЪЕДАН
switch(mode):
  3 (ВВЕРХ)  → слотовый A 0x0E08D8B0, IPC-семейство 0x95
  4 (ВНИЗ)   → слотовый B 0x0E08D8D4, IPC-семейство 0x96
  5 (ВЛЕВО)  → 0x0E08CE10: следующий включённый слот (по маске [0x23008BCE],
               slot+1, >4 → поиск с 0) → IPC {0x93, 0, 0, slot} → push 0x1B
               (0x0E08CBB0); вход в слот 4 → сначала 0x0E093F58 (сброс KPS)
  6 (ВПРАВО) → 0x0E08D7EC: предыдущий включённый слот (slot−1, 0 → 4) → то же
ХВОСТ (0x0E08D880): если [0x23002348]==0 (экран спал) → [0x2301D249]=1 + IPC
  яркости 0x0E08C3FC([0x230086BC + 0x4B2 + page]); всегда [0x2300128C] = 0x1E
  (сброс диспoeвого таймера простоя)
```

### 2.1 Слотовый A — ВВЕРХ (0x0E08D8B0), свитч по текущему слоту [0x23000C98+9]

Таблица слов @0x0E08D8C0. Слот > 4 → 0x0E08D868 (мёртвая ветка, слотов всего 5).

| Слот | Действие | IPC |
|---|---|---|
| 0 (баннер) | `[0x23014C34]==1` (баннер активен): баннер-парам [0x23014C24] **−1** (пол 1) → IPC `{0x24, v}`. Иначе: page==7 → закрытие bitmap-вида (0x0E083B88(100) + конверт **0x127** + `[0x2301D24A]=*0x23012A0C`); иначе **page −1** (wrap 0→5; 6 доступен только при бите 0x40 `[0x23014B48]`) + 0x0E0893B0 (RGB-мейлбокс) + яркость страницы + IPC `{0x13, dev, page}` | 0x24 / {0x13} / **0x95** |
| 1 (часы) | тоггл бит1 [0x23014B49] — формат 12/24ч + флеш-сейв | **0x95** |
| 2 (батарея ПК) | тоггл бит2 [0x23014B49] — % ↔ иконка + флеш-сейв | **0x95** |
| 3 (мониторинг) | collect 0x0E08C1A4 + отправка — redraw-only, страниц не меняет | **0x95** |
| 4 (KPS) | 0x0E093F58 (сброс KPS-кольца) + collect | **0x95** |

### 2.2 Слотовый B — ВНИЗ (0x0E08D8D4), tbb @0x0E08D8E0

То же самое с симметрией «вперёд» и IPC **0x96**:

| Слот | Действие | IPC |
|---|---|---|
| 0 | баннер-парам **+1** (потолок 3); иначе: page==7 → закрытие bitmap-вида (0x0E083B88(100) + конверт **0x27** + `[0x2301D24A]=*0x23012A0C`); **page +1** (wrap 6→0; 6→0 и при запрете) + IPC `{0x13, dev, page}` | 0x24 / {0x13} / **0x96** |
| 1 | тоггл бит1 (12/24ч) + флеш-сейв | **0x96** |
| 2 | тоггл бит2 (%↔иконка) + флеш-сейв | **0x96** |
| 3 | collect + отправка | **0x96** |
| 4 | 0x0E093F58 + collect | **0x96** |

### 2.3 Общий колектор 0x0E08C1A4 (payload 0x94/0x95/0x96)

`buf[0] = slot<<4` (слот 0: `+3` при активном баннере, `+1` при page 6, `+2` при
page 7); `buf[1]`: слот 1 → `!бит1 [0x23014B49]` (сейчас 12/24), слот 2 → `бит2`
(сейчас иконка/%), слот 0+баннер → нибблы времени `[0x23014C24] | [0x23014C28]<<4`,
прочие → 0. Для слота 3 всегда `{0x30, 0x00}` — в точности константа
`03 96 00 00 30 00…` из живых логов (направления в payload НЕТ).

### 2.4 Отправитель IPC app→sysctrl

- 0x0E09220C(type, a1, a2, buf, len) — конверт `{type, a1, a2, payload[len]}` в
  2-глубокое кольцо (@указатель [0x230011E8], записи по 24 Б; флаг-таймер
  конверта [0x2300127C]).
- 0x0E09217C(type, 0, 0, слот) — то же для коротких {0x93}.
- 0x0E083A38(buf, len) / 0x0E083A98 / 0x0E083B88 — сырые конверты (первый байт =
  тип): 0x11/0x12/0x13/0x14/0x16/0x19/0x1A/0x1B/0x1C/0x1D/0x1E/0x1F/0x24/0x25.
- Зеркало на iface2 (`03 <type> …`, report ID 3, 20 Б, ep 0x83) байт-в-байт
  повторяет эти конверты. Точный flash-адрес периодического отправителя
  `03 95` НЕ найден: BL-sweep всех отправителей (0x0E09220C — 3 сайта,
  0x0E09217C — 12, 0x0E083A38 — 28) других мест с типом 0x95 не дал, а в
  sysctrl-образе 0x95/0x96 встречаются только как номера IRQ/таймауты k_sleep
  (ложные срабатывания). Кандидаты: дренаж кольца из RAM-кода (аналог RAM-колбэков
  LED, PROTOCOL_OLED §7) или реэмит последнего конверта по тикеру ~0.86 с.
  Для вердикта по ВВЕРХ это не критично — кадр heartbeat и жест-ВВЕРХ совпадают
  байт-в-байт при любом провайдере.

### 2.5 Wake-гейт [0x2301D249] — все писатели

| Кто | Значение | Когда |
|---|---|---|
| хендлер `65` (мега-хендлер 0x0E08CE6C, case 0x65): v = pkt[4] ≤ 2 | **1** (жесты ЕДЯТСЯ) | wake/показ (`65 00/01/02`; v=0 = вид «Mail») |
| хендлер `65`: v > 2 (в т.ч. **0xFF**) | **0** (жесты РАЗРЕШЕНЫ) | `65 FF` GearLink/прототипа |
| хвост диспетчера 0x0E08D84C (и дабл-тап 0x0E08DB58) | 1 | первый жест при спящем экране ([0x23002348]==0) — экран разбудили, жест съеден |

⚠ Наблюдение «65 FF взводит гейт жестов на ~30–60 c» (живые тесты) кодом НЕ
подтверждается: 65 FF гейт как раз СНИМАЕТ. Похоже, наблюдённое «глухое окно» после wake —
это бит0-переход [0x23002348] (первый жест будит экран и съедается хвостом, гейт
остаётся взведённым до ближайшего `65 FF`). Проверить живьём: после «глухого
окна» послать `65 FF` — свайпы должны ожить мгновенно.

## 3. ВЕРДИКТ по «вверх»

1. **Хендлер существует и отрабатывает полностью**: mode 3 (ВВЕРХ) на слоте 3 →
   collect + IPC `{0x95, 0, 0, 0x30, 0}` (0x0E08D868). Обрыва/глотания ветки нет
   (глотается только wake-гейтом, как и любой другой жест).
2. **Хосту событие неотличимо**: тип 0x95 = тот же, что у фонового стрима
   состояния виджетов (~0.86 с, payload {slot<<4, sub} константен на слоте 3).
   Ни флага направления, ни отдельного типа, ни регистра «последний жест» нет —
   что и подтвердил `swipereg.py`. ВНИЗ уникален только потому, что тип 0x96
   больше никем не отправляется.
3. **Условия/конфига, включающего «вверх», НЕ существует**: ветки зашиты в
   tbb/таблицы слов флеша; ни один конфиг-байт на выбор 0x95/0x96 не влияет.
   «Листание назад» карусели хоста (0x66-селекторы) прошивкой не поддерживается
   by design: страницы мониторинга — состояние хоста, клавиатура шлёт лишь
   «событие жеста».
4. **Тайминговая проверка логов (2026-10-05, пост-анализ scan_up.log /
   scan_swipe.log)**: кадр ВВЕРХ не выделяется и фазой — 0/10 EVT-96 сидят в
   пределах 150 мс от соседнего 0395 (отправка немедленная, не «в слот тикера»),
   а интервалы 0395 в окнах жестиления местами учащаются (5 шт < 0.7 с, min
   0.461 — вероятные следы жестовых 0395/рестартов тикера). Но эвристику
   «пришёл лишний 0395» построить нельзя: сам тикер гуляет 0.70–1.26 с
   (p25–p75 в свайп-сессии), останавливается на 20–39 с, и учащения коррелируют
   с любыми жестами, не только ВВЕРХ. Итог: **сигнатура ВВЕРХ = сигнатура
   heartbeat по построению** (один тип + один колектор payload), хостом
   невыделаема ни по содержанию, ни по надёжному таймингу.
5. Практическое следствие: **exact GearLink — листание только вперёд
   по 0396** (уже реализовано). Для «назад» единственный незанятый жест —
   **дабл-тап → `03 94`** (§0.5): семантика «назад» навешивается хостом, но надо
   принять побочку (toggl бит0 [0x23014B49] + флеш-запись ~на каждый дабл-тап).

## 4. «Карусель» слота 4 — на самом деле KPS-история

- **Сброс 0x0E093F58** (вызывается при ВХОДЕ в слот 4 с соседнего слота — из
  0x0E08CE5E (mode 5) и 0x0E08D83C (mode 6) — и при любом ВЕРТИКАЛЬНОМ жесте на
  самом слоте 4 — 0x0E08D864 (ВВЕРХ) / 0x0E08D8EC (ВНИЗ)): зануляет idx/ячейки/
  total/max и шлёт IPC `{0x25, 0}` (0x0E08DC00).
- **Писатель 0x0E093F9A** (адрес 0x0E093F9E из прошлой сессии — метка внутри;
  пролог на 0x0E093F9A, перед ним хвост соседней функции с насыщающим счётчиком
  [0x23017BE8]):
  - `[0x23019018 + idx]` = аккумулятор ([0x23019020]); `total` ([0x23019010])
    корректируется на разницу; `idx = (idx + 1) % 5` — **wraparound 0..4**;
    `max` ([0x2301900C]) обновляется;
  - IPC **{0x25, флаг [0x2301D273], total(u16), max(u16)}** через 0x0E08DC00 →
    sysctrl рендерит нативный тайл KPS слота 4 (график = 5 ячеек ринга).
  - Гейт отправки: байт [0x2301D272] != 0 → без IPC (тихое обновление).
- Т.е. вертикальный свайп на слоте 4 НЕ «листает страницы», а сбрасывает график
  KPS; страницы слота 4 хостом не управляются (GearLink их тоже не трогает).

## 5. Сводка «жест × слот → событие на шине iface2»

| Жест | Слот 0 (баннер) | Слот 1 (часы) | Слот 2 (батарея) | Слот 3 (мониторинг) | Слот 4 (KPS) |
|---|---|---|---|---|---|
| **ВВЕРХ** (mode 3) | `0395` (или `0324…`? — конверт {0x24,v} в IPC, баннер-парам −1; page±: `0393`+`0395`) | `0395` | `0395` | `0395` ← **невидим в heartbeat** | `0395` (+сброс KPS) |
| **ВНИЗ** (mode 4) | `0396` (баннер-парам +1; page+: `0393`+`0396`) | `0396` | `0396` | **`0396`** ← единственный видимый | `0396` (+сброс KPS) |
| **ВЛЕВО** (mode 5) | `0393 <slot+1>` | ← | ← | ← | ← (+сброс KPS при входе в 4) |
| **ВПРАВО** (mode 6) | `0393 <slot−1>` (wrap 0→4) | ← | ← | ← | ← (+сброс KPS при входе в 4) |
| **Дабл-тап** | `0394` (везде; + тоггл бит0 [0x23014B49] + флеш-сейв) | ← | ← | ← | ← |

(примечание: `0393 00 00 <slot>` в логах = абсолютный номер нового слота —
сходится с `scan_up.log` 00:13:12–30, где пользователь циклил слоты 0..4).

  направлений, слот-контекст байта 4); карта событий iface2 обновлена
  (95=heartbeat / 96=ВНИЗ / 94=дабл-тап / 93=слот±1); «нестабильность
  вертикальных свайпов» объяснена; строка «65 FF взводит гейт» помечена как
  противоречащая коду (v≤2 ставит, v>2 снимает) с планом живой проверки;
  «карусель» в разделе «Слот 4» пере-атрибутирована.

## 7. Открытые вопросы

1. Flash-адрес периодического отправителя `03 95` (heartbeat ~0.86 с) — не
   локализован (§2.4); гипотеза — RAM-код/дренаж кольца.
2. Микроструктура тикера в окнах жестиления (учащение до ~0.55–0.65 с, §3 п.4):
   инжектирует ли UP собственный 0395-кадр или жест рестартует тикер — не
   разделено (нужна сессия с ms-лейблами свайпов); на практическую выводимость
   не влияет.
3. Семантика бит0 [0x23014B49] (тогглится дабл-тапом): кандидат «экран вкл/выкл».
   Живой тест: дабл-тап → смотреть экран/`23 02`.
4. Полярность wake-гейта в живом поведении после wake (§2.5) — окно «глухих
   свайпов» после `65 FF` объясняется хвостом диспетчера, не самой `65`.
5. Полная семантика конвертов 0x127/0x27 (закрытие bitmap-страниц, 0x0E083B88/
   0x0E083A98) — только эскизно (§2.1 слот 0, page 7).
